- **새 악보:** 멜로디 1파트, 보컬 1파트, 보컬+피아노 양손(2개 악기 파트, 피아노는 하나의 그랜드 스태프) 템플릿. 4/4, 초기 4~32마디. 기존 악보는 .musicxml / .xml / .mxl / .mid / .midi로 불러올 수 있습니다.
- **음표 작성:** 3.0 편집기의 마디·쉼표 선택과 음정·길이 입력을 연결해 보통 쉼표를 원하는 길이의 음표로 치환하고 잔여 박자를 쉼표로 정확하게 분할합니다. 원본 문서는 변경하지 않고 DOM 사본에 적용하며, 박자가 애매하거나 복잡한 다성부에서는 수정하지 않습니다.
- **새 악보 확장:** 4/4 단일 보표로 구성된 파트에 완전한 빈 마디 1~16개를 일괄 추가(총 128마디까지). 복잡한 성부·박자 변화는 보호합니다.
- **기보:** 템포(BPM 30~240), pp~ff 셈여림, 스타카토·테누토·악센트 추가/해제, 파트 전체 조표(-7~+7) 및 MusicXML system/page break. 이는 원본 악보의 피치를 자동 이조하지 않습니다. OSMD에서 악보 나눔을 정확히 표시하는지는 실제 렌더링 확인이 필요합니다.
- **간이 청음:** 다성부/화음/단순 붙임줄을 감안한 MusicXML 시간표와 Web Audio 삼각파 재생. 악상 표현·이조 악기·음색·페달·오디오 믹싱은 전문 재생 결과를 보증하지 않으며, 실제 음원 또는 Logic을 대체하지 않습니다.
- **임시 저장:** 이 브라우저 기기의 IndexedDB에 마지막 8개 악보를 파일 이름별로 임시 보관(개별 XML 8MiB 이하). 복원은 사용자가 명시적으로 선택할 때만 실시하며, 업로드·클라우드 동기화는 하지 않습니다. 비공개 브라우징, 데이터 삭제, 저장소 한도 상황에서는 작동하지 않을 수 있으므로 **반드시 MusicXML을 별도로 다운로드해서 백업**해야 합니다.
- **출력:** 기존 A4 브라우저 PDF 인쇄 및 JPEG 기반 파트별 PDF ZIP에 더해, 현재 화면의 SVG 벡터 페이지 ZIP을 제공합니다. SVG는 글꼴 자체를 내장하지 않으므로 인쇄 전에 표시·간격·페이지 넘김을 검수해야 합니다. 직접 벡터 PDF가 필요하면 브라우저의 PDF 인쇄 경로를 사용합니다.
- **단일 편집 이력:** 4.0 기보 작업은 기존 V3 \`commitExternal\`의 40단계 실행 취소/다시 실행·원본 보호·렌더 오류 시 되돌리기를 재사용합니다.

## J-WOO 4.0 통합 작곡 기능 확장 — 가사·연결 기보·벡터 파트보·곡 중간 설정

- **여러 절의 가사:** MusicXML `lyric@number` 1~12절, 유니코드/한국어 텍스트, syllabic(single/begin/middle/end), melisma `extend`(start/continue/stop), 선택 절별 수정·삭제. 음표의 기존 성부·음정·리듬은 바꾸지 않습니다.
- **실제 붙임줄:** 같은 음정/성부/보표의 연속 음표를 현재 마디 또는 다음 마디까지 연결·해제하며, 재생용 `tie`와 기보용 `notations/tied`를 **함께** 삽입/제거합니다. 불일치하는 연결을 무리하게 고치지 않습니다.
- **곡 중간 조표:** 선택한 마디에 모든 파트의 `key/fifths`를 삽입합니다. 음정 자체의 반음 이동·이조를 의미하지 않으며 실제 악상은 확인해야 합니다.
- **빈 구간 박자표:** 선택 마디부터 마지막 마디까지 비어 있는 성악/피아노 보표의 음표 대신 쉼표·backup 길이를 2/4, 3/4, 4/4, 6/8, 3/8, 2/2에 맞게 정확히 갱신합니다. **이미 작성된 구간은 자동 rebar가 아니므로 차단**됩니다.
- **A4 벡터 악보 책자:** 각 악기 파트를 독립적으로 OSMD/SVG 렌더링하고 모든 파트의 페이지를 한 새 창에 모아 브라우저의 인쇄/PDF 저장 기능으로 내보냅니다. 이 새 경로는 기존 JPEG 기반 파트별 PDF ZIP과 달리 SVG를 JPEG로 바꾸지 않습니다. 페이지 수/글꼴/줄 바꿈은 실제 인쇄 미리보기에서 검수해야 하며, 자동 개별 벡터 PDF ZIP 생성까지 구현된 것은 아닙니다.
- **검증:** 합성 악보의 가사·붙임줄 MusicXML 왕복/재불러오기, 결합된 붙임줄의 간이 청음, 피아노 양손/성악 빈 구간 3/4 전환, 복수 파트 SVG 인쇄를 Chromium에서 검증하고, 불량 입력 차단·원본 불변을 Node 테스트로 확인합니다.

이 추가 개발은 4.0 출시 목표의 일부입니다. **MusicXML XSD 전체 검증, 실제 Logic Pro 내보내기 왕복 코퍼스, 전문 자동 조판 충돌 분석, 모든 음표/튜플릿의 자유로운 리듬 재배치, 완전한 그랜드 스태프 악보 품질, 독립 벡터 PDF ZIP**은 아직 최종 합격 기준에 미달합니다.

## J-WOO 4.0 전문 기보 편집 확장 (보수적 지원 범위)

기존 4.0 신규 작곡·MXL 불러오기·악보 청음·임시 저장에 다음 음악 기보 기능을 실제 연결했습니다.

- **다성부/피아노 보표의 개별 음표 길이 변경:** MusicXML의 `backup`·`forward`를 유지하고 같은 성부의 **바로 뒤 일반 쉼표만 소모**해 음표 길이를 늘립니다. 길이를 줄일 때는 남는 시간을 동일 성부/보표의 쉼표로 채웁니다. 다른 성부의 음표 시간·피치·길이가 바뀌면 작업을 거부합니다.
- **다성부 쉼표→음표 삽입:** 동일한 시간 보존 방식으로 성부와 보표 정보를 유지하며, 남는 쉼표를 박자에 맞게 나눕니다.
- **그랜드 스태프 작곡:** 새 보컬+피아노 템플릿은 Piano 1개 파트 아래 높은음/낮은음 두 보표(별도 voice 1·2, backup)를 생성합니다. 동일한 안전 편집 엔진으로 각 손의 쉼표에 음표를 입력하며, 보표별 박자가 완성되어 있으면 빈 마디를 추가할 수 있습니다.
- **정확한 3:2 8분 셋잇단음:** 같은 보표·성부 안의 한 박자에 있는 8분음표 2개를 가운데 음정 명시 입력으로 3개로 변환합니다. `duration`, `time-modification`, 시작·끝 `tuplet` 및 독립된 8분음표 빔을 연결합니다. `divisions`이 정확히 6의 배수인 경우만 지원합니다. 신규 악보는 이를 위해 divisions=48로 생성합니다.
- **이음줄·크레셴도·디미누엔도:** 같은 마디의 동일 성부·보표 두 음표에 slur 기보를 연결/해제하고, MusicXML 방향 기호(`wedge`)를 넣습니다.
- **중요:** 다성부 입력은 구버전 3.0 입력창 비활성 상태와 관계없이 4.0의 독립적인 음정·음길이 입력 컨트롤에서 사용합니다.

**제한:** 붙임줄·기존 셋잇단음·임의 빔을 포함한 음표 길이 변경, 복합 화음의 리듬 재배치, 임의의 5:4/7:4 튜플릿, 악보 전체 자동 리플로우와 충돌 제거, 전문 벡터 PDF 파트별 일괄 출력, 실제 Logic Pro MusicXML 왕복 실전 검증은 아직 완성하지 못했습니다. 이 확장은 전문 악보 프로그램 완전 대체 인증이 아니며, 최종 악보는 반드시 시각·청음 검수를 거쳐야 합니다.

## 지원 범위

- 입력: `.musicxml`, `.xml`, `.mxl` (MusicXML partwise)
- 정리: 제목·작곡가·파트 이름 수정, 파트별 미리보기 표시/숨기기, 확대/축소, A4 세로/가로 레이아웃 선택, **리듬·쉼표 검사와 일부 쉼표 병합**
- 출력: 수정한 전체 `.musicxml`, 개별 파트 `.musicxml`, **전체 파트 MusicXML ZIP** 다운로드, 전체/선택 파트를 브라우저 인쇄 기능으로 PDF 저장
- 미지원: Logic `.logicx` 직접 열기, 오디오 자동 채보, MIDI 음표 타이밍 복원·자유 편집, 복잡한 쉼표 재기보, 재생

Logic Pro에서 **파일 > 내보내기 > 악보를 MusicXML로** 내보낸 다음 이 사이트에서 여세요. 오디오만 있는 트랙은 먼저 MIDI/노트 데이터가 필요합니다.

## 개별 파트보 출력

악보 파일을 연 다음 **파트 선택 → 선택 파트 보기 → PDF로 인쇄** 순서로 개별 파트보를 만듭니다. **전체 파트 보기**로 원래 미리보기 상태를 되돌릴 수 있습니다. 선택 파트 MusicXML 저장은 다른 악보 편집기에서 추가 편집할 때 사용합니다. 인쇄 방향은 미리보기의 **용지 방향**에서 선택하고, 브라우저 인쇄 대화상자에서도 용지 방향과 배율을 확인하세요. 현재 단순 쉼표 병합 기능은 별도이며 음표 리듬 자동 교정이나 자동 PDF 일괄 저장을 제공하지 않습니다.

## 파트별 MusicXML 일괄 다운로드

1. Logic에서 MusicXML을 내보내고 J-WOO에서 엽니다.
2. 왼쪽 **개별 파트보 → 전체 파트 MusicXML ZIP 저장**을 누릅니다.
3. 각 파트를 분리한 `.musicxml` 파일이 번호 및 파트 이름과 함께 ZIP에 저장됩니다. 이름이 같은 파트도 번호로 구분합니다.

파일은 브라우저 내부에서만 생성되며 서버에 업로드하지 않습니다. 음표의 리듬은 자동 교정되지 않습니다. 현재 **파트별 PDF 일괄 생성**은 지원하지 않으며, PDF는 파트를 선택한 뒤 브라우저 인쇄 기능으로 별도 저장해야 합니다.

## 리듬·쉼표 검사 (3차)

파일을 열면 왼쪽 **리듬·쉼표 검사**에서 안전한 쉼표 병합 후보와 검토가 필요한 짧은 음표·쉼표를 확인할 수 있습니다.

- **다시 검사**: 읽기 전용 검사. 원본 MusicXML을 변경하지 않습니다.
- **안전한 쉼표 정리 적용**: 사용자가 명시적으로 누른 경우에만 인접한 16분쉼표 2개 → 8분쉼표 1개, 또는 8분쉼표 2개 → 4분쉼표 1개로 병합합니다. 2/4, 3/4, 4/4의 단일 성부, 완전한 마디, 박자 경계 정렬, 단순 표기만 허용합니다. 반복 패스로 4개의 16분쉼표를 4분쉼표로 묶을 수도 있습니다.
- **정리 되돌리기**: 브라우저 메모리에 보관된 직전 문서를 복원합니다. 새 파일을 열거나 곡/파트 정보를 수정하면 되돌리기 기록은 폐기됩니다.

혼합 성부, 이음줄/붙임줄 특수 처리, 복수 보표, 셋잇단음, 복잡한 쉼표 속성, 불완전 마디, 6/8 등 복합 박자에서는 **정리하지 않습니다**. 음표의 피치·연주 길이·템포는 변경하지 않으며 복잡한 짧은 음표는 위치만 보고합니다. 원본 파일을 별도로 보관하고 결과를 재생 가능한 악보 프로그램에서 확인해 주세요. 브라우저 UI 및 Logic Pro의 다양한 실파일 조합에 대해서는 별도 검증이 필요합니다.

## J-WOO Score Studio 2.0 통합 후보 (공개 배포 전 검증)

**리듬·기보 검사:** 실제 MusicXML의 `<duration>`과 `<type>`이 다른 **단순 무부점 음표**만 제안합니다. 2/4·3/4·4/4 완전한 단일 성부 마디에서, 붙임줄·빔·셋잇단음·여러 보표·장식된 음표 등을 보수적으로 제외합니다. MIDI 원연주의 실제 타이밍을 복원하거나 자동으로 퀀타이즈하지는 않습니다. 사용자가 체크한 후보만 원본 사본에 적용하고, 수정 전후 미리보기를 전환할 수 있습니다.

**변경 비교:** 원본을 불러온 시점의 악보와 현재 악보를 마디별로 비교합니다. 음표·쉼표의 기보 종류, 길이, 피치, 기본 가사 정보를 비교하지만 악상 기호의 모든 시각적 변화나 편곡상 차이를 검출하는 기능은 아닙니다. 파일을 다시 열면 비교 기준은 새 원본이 됩니다.

**레이아웃:** 자동 추천(가사가 있으면 여유 있게, 악기가 많으면 조밀하게)과 표준·여유·조밀 수동 프리셋을 제공합니다. OSMD의 간격 규칙을 소폭 조정하는 방식이며 자동 충돌 제거와 지능형 페이지 조판을 보증하지 않습니다.

**파트 PDF ZIP:** 기존 MusicXML ZIP과 별도로, 각 파트를 OSMD SVG로 렌더링해 브라우저 내 JPEG 기반 PDF로 변환한 다음 ZIP으로 묶습니다. 파일은 네트워크로 업로드하지 않습니다. A4 세로·가로를 지원하지만 벡터 PDF가 아니라 **이미지 기반 PDF**이며 브라우저별 글꼴·기보 표시가 달라질 수 있습니다. 최대 12개 파트, 파트당 14페이지, 총 80페이지를 넘으면 작업을 중단합니다. 파트 하나라도 실패하면 ZIP 파일을 제공하지 않습니다.

**검수 범위:** 자동 테스트는 문법·구조·정적 후보 처리·PDF 바이트 형식을 검증합니다. Logic Pro의 실제 내보내기 파일, 다성부 복잡한 악보, 브라우저 SVG→PDF 렌더와 인쇄 결과는 별도 실기 검증이 필요합니다. 음악적 판단 없이 자동으로 수정 내용을 저장하지 않으며, 원본 MusicXML은 브라우저 밖에서 수정되지 않습니다.

## J-WOO 3.0 편집 엔진 후보 — 공개 배포 전

이 브랜치에서는 기존 V1·2.0의 악보 보기, 일괄 MusicXML/PDF 출력, 원본 비교 및 안전한 리듬 후보 기능을 유지하고, 직접 편집기와 변경 이력 기능을 연결합니다.

### 구현 기능

- **MusicXML 편집 데이터 모델:** 파트, 마디, 박자, divisions, 음표·쉼표, 길이, 음정, 가사와 음표 시작 위치를 읽기 전용으로 인덱싱합니다.
- **마디별 음표 선택:** 왼쪽 편집 화면에서 파트·마디를 선택하고 음표/쉼표 항목을 클릭하거나 방향키로 이동합니다. **악보 SVG 위에서 음표를 직접 드래그하는 기능은 아직 없습니다.**
- **음정:** 반음·온음과 옥타브 입력을 통해 피치를 변경하며 원래 길이는 유지합니다.
- **길이:** 음표를 줄일 때 남은 길이를 쉼표로 채우고, 늘릴 때는 직후 일반 쉼표를 소모합니다. 정확한 길이로 분해할 수 없으면 전체 변경을 거부합니다.
- **음표 삭제·추가:** 기존 음표를 동일 길이의 쉼표로 치환하거나 일반 쉼표를 음표로 치환합니다. 화음이나 성부를 임의로 삭제하지 않습니다.
- **붙임줄:** 같은 높이의 연속 음표 두 개 사이에 단순 붙임줄을 생성·해제할 수 있습니다. 기존의 복잡한 연결은 보존합니다.
- **가사:** 단순한 1절/1음절 가사 입력·삭제를 지원합니다. 여러 절·멜리스마·복잡한 가사 구문은 보호합니다.
- **실행 취소·다시 실행:** 최대 40개 악보 사본을 메모리에 보관하며, 기존 1·2차 편집 작업이 실행되면 3.0 이력을 초기화합니다.
- **기존 출력 기능 연동:** 변경된 MusicXML을 기존 전체/개별 파트 및 PDF 출력 대상으로 사용합니다. PDF 출력 자체는 별도의 브라우저 실기 검증이 필요합니다.

### 안전 범위와 미지원

지금 단계의 직접 편집은 **완전한 단일 성부의 2/4, 3/4, 4/4, 6/8 마디**를 대상으로 하며, 박자·분할 정보가 없거나 마디 길이가 불완전한 경우 수정하지 않습니다. 현재 직접 수정하지 않는 대상은 **화음, 다성부 백업/포워드, 복잡한 붙임줄·이음줄 및 빔이 있는 음표, 셋잇단음, 장식음, 여러 보표, 복수 절 가사**입니다. 그 밖에 원본 기보를 변경할 수 있는 모호한 상황은 차단합니다.

이 브랜치만으로 Logic Pro의 악보 편집기를 완전히 대체한다고 주장하지 않습니다. **MIDI 파일 직접 가져오기**는 제한적으로 지원합니다. **악보 SVG에서의 직접 드래그 편집, 전문 조판, 정확한 셋잇단음/다성부 자유 편집, 실연주 타이밍 복원**은 현재 미구현입니다.

### 검증

합성 MusicXML DOM fixture의 음표 변경, 가사, 길이 보존, 복잡한 마디 차단, 실행 취소 및 기존 CI/빌드를 자동 검사합니다. 실제 Logic Pro에서 내보낸 MusicXML, 실제 브라우저의 OSMD 기보·가사·PDF 출력 품질은 별도 수동 검증 전까지 미확인으로 유지합니다.

### MIDI (.mid/.midi) 가져오기 (V3 후보)

MusicXML과 함께 **표준 MIDI 파일 형식 0·1**을 선택할 수 있습니다. 16분음표 단위로 음표 시작·종료를 **명시적으로 양자화한 새 MusicXML**을 생성하며, 원본 MIDI 파일 자체는 바꾸지 않습니다. 가져오기 결과 메시지에는 양자화로 시점/길이가 변경된 음표 개수 및 악기·마디 수를 표시합니다.

지원 범위는 PPQ 시간 기반 단일 성부의 피치 악기 트랙, 제한된 2/4·3/4·4/4·6/8 박자, 최대 12개 악기 파트·4,000음표·300마디입니다. **겹치는 음표, 드럼 채널, 페달 유지, 피치벤드, 곡 중간 박자 변경, SMPTE 시간 형식, 지나치게 큰 MIDI는 자동 변환하지 않습니다.** 자동 양자화는 연주 의도를 완벽하게 보존한다고 보장할 수 없습니다. Logic에서 내보낸 MusicXML을 우선 사용하고 MIDI 원본과 결과를 반드시 대조해야 합니다.

## J-WOO 3.0 고급 악보 편집 확장 · PR #5 추가 개발

- **악보 위 직접 선택/피치 드래그 후보:** OSMD SVG의 실제 음표 머리 그래픽과 MusicXML 음표 인덱스가 완전히 일치하는 경우에만 이벤트를 연결합니다. 단일 파트 보기 + 단일 보표·성부 + 음표만 있는 단순 마디로 범위를 제한합니다. 클릭·키보드 방향키(위/아래)로 음높이를 한 단계씩 이동하거나 수직 드래그로 음높이를 조정할 수 있습니다. 드래그 간격은 시각적 추정치이므로 실제 브라우저의 악보 렌더링을 추가 검증해야 합니다. 여러 보표·화음·다성부·쉼표가 섞인 마디는 잘못된 음표 선택을 방지하기 위해 SVG 편집을 차단합니다. 이 경우 왼쪽 패널을 사용합니다.
- **고급 MusicXML 시간표:** 백업/포워드, 성부(voice), 보표(staff), 화음 시작점, 셋잇단음 비율을 별도로 식별합니다. 비정상 시간 이동·성부 내부 겹침과 모호한 구조는 편집을 차단합니다.
- **고급 제한 편집:** 여러 성부·화음·셋잇단음에 포함된 음표의 음높이를 수정할 수 있습니다. MusicXML duration, backup, forward, time-modification은 그대로 보존합니다. 단순 화음의 구성음을 추가/제거할 수 있으며, 한 음표의 이음줄·장식음/악상기호가 복잡하면 수정하지 않습니다.
- **안전한 변경 이력:** 고급 편집도 기존 3.0의 실행 취소·다시 실행 기록을 사용합니다.

**여전히 미지원:** 복잡한 다성부·셋잇단음의 길이 자유 편집, 다른 보표로 드래그 이동, 화음의 다중 붙임줄 편집, 전문 악보 조판 전체, Logic 원본과의 실기 비교 및 최종 PDF 시각 검수. 자동 합성 테스트와 Vite 빌드 통과는 실제 연주자용 악보 출고 검증을 대체하지 않습니다.

### 실제 Logic MusicXML 검증 절차

GitHub CI에서는 다성부·피아노 양손 보표·화음·셋잇단음을 포함하는 **합성 MusicXML 2개**에 대해 독립된 Python 표준 라이브러리 기반 시간표/피치 비교기를 실행합니다.

실제 Logic에서 내보낸 악보를 사용자가 제공하면 다음 명령을 통해 원본의 성부별 시간 위치, 음표 길이, 화음·셋잇단음·붙임줄·가사 구조를 조사하고, 수정본과 비교할 수 있습니다.

    python3 tests/audit_musicxml.py ORIGINAL.musicxml --compare EDITED.musicxml --allow-pitch

이 검사기는 원래 음정 외의 시간표·성부·화음·셋잇단음 정보가 바뀌면 출고 전 검토 대상으로 차단합니다. 단, **모든 MusicXML 구조·레이아웃·악상기호를 포괄하지 않으므로 악보의 독립적 음악적 품질 인증은 아닙니다.** 최종 PDF 인쇄 품질과 실제 Logic 왕복 호환성은 실제 악보와 브라우저를 이용한 사람의 검수가 필요합니다.
